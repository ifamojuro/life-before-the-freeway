1. The shape of the repo

Two independent apps in one repo, plus a tools/ script that generates the static basemap images. No monorepo tooling — you cd into each side.

impl/ ├── backend/ FastAPI + SQLAlchemy + SQLite (~1,750 lines) │ ├── app/ │ │ ├── main.py app factory, lifespan (create tables + seed), /uploads static mount │ │ ├── config.py env vars + the canonical ERAS list │ │ ├── db.py engine, SessionLocal, get_db() │ │ ├── auth.py bearer-token staff auth (salted SHA-256 — not prod-grade) │ │ ├── models.py 8 ORM tables │ │ ├── schemas.py Pydantic in/out shapes (mirrored by frontend/src/lib/types.ts) │ │ ├── seed.py sample archive + staff accounts, runs on every startup (idempotent) │ │ ├── routers/ public.py · submissions.py · admin.py │ │ └── services/ rag.py · transcription.py · places.py │ ├── tests/ 9 pytest tests via TestClient; conftest points at a temp SQLite │ └── Makefile make dev / test / reset-db ├── frontend/ React 18 + TS + Vite, react-router v6 — no map library (~4,200 lines) │ ├── public/basemaps/{1950,1965,1985}.jpg USGS topo scans (generated by tools/) │ └── src/ │ ├── App.tsx routes; everything but Home is lazy() │ ├── lib/ api.ts · types.ts · geo.ts · device.tsx · util.ts │ ├── components/ MapView · ChatPanel · Recorder · UploadPicker · EraControl … │ ├── pages/ home/ · story/ · contribute/ · admin/ · info/ │ └── styles/ plain CSS, tokens.css holds the design system ├── tools/build_basemaps.py GeoTIFF → warped JPG per era └── docs/historical-maps.md map source research + the implementation note
Mental model The backend is a thin CRUD + moderation API with two "smart" services (RAG chat, transcription/place-extraction) that both have deterministic offline modes. The frontend is a conventional SPA — React Router + fetch, no state library, no SSR. The map is a self-contained component with zero external dependencies.

2. Run it in 2 minutes

# terminal 1 — API on :8000 (creates .venv, seeds lbtf.db on first start)
cd backend && make dev

# terminal 2 — web on :5173 (proxies /api and /uploads → :8000)
cd frontend && npm install && npm run dev
  • Public: http://localhost:5173. Admin: /admin/login — randolph@lbtf.org / admin (super-admin); maya@, jordan@ are moderators.
  • Force a layout: ?layout=mobile or ?layout=desktop (sticks for the session via sessionStorage).
  • Tests: cd backend && make test. Frontend has no tests; npm run build is the typecheck gate (tsc -b && vite build).
  • Wipe state: make reset-db deletes lbtf.db + uploads/; the seed re-runs on next boot. Seed data changes only show up after a reset.
  • The whole thing runs offline: no map tiles, no API keys. Set ANTHROPIC_API_KEY only if you want Claude-composed chat answers.

3. Backend walkthrough

Startup: app/main.py

Lifespan handler does Base.metadata.create_all() then seed(db). There are no migrations — adding a column to an existing lbtf.db means make reset-db. Three routers are included, plus a StaticFiles mount at /uploads for raw video.

Routers (all under /api)

FilePrefixAuthWhat lives there
routers/public.py/apinoneGET /eras, GET /locations[?era=] (pins — only locations with ≥1 published story), GET /locations/{id} (stories + comments), POST /locations/{id}/comments, GET /prompts, GET /prompts/random, POST /chat
routers/submissions.py/api/submissionsnonePOST /upload (multipart; streams to disk with a 250 MB cap, then synchronously transcribes + extracts places, returns an Upload row), POST "" (turns an upload + contributor form into a pending Submission)
routers/admin.py/api/admincurrent_staff bearerlogin/logout/me, queue list + detail, PUT …/associations, POST …/approve, POST …/reject, POST /field-capture (publishes directly), published list + unpublish, audit, staff list, gazetteer (/locations)

Auth: app/auth.py

Login issues a random token stored on the Staff row (one active session per staff member). current_staff is a FastAPI dependency reading Authorization: Bearer …. require_super_admin exists but is barely used yet. Password hashing is salted SHA-256 — the file itself says swap for bcrypt/argon2 before production.

Services

  • services/rag.py — answer(db, question, history) → (text, passages, mode). retrieve() is a hand-rolled BM25 over every published Story (transcript + caption + location name), recomputed per request, with prefix soft-matching. Then either _compose_with_claude (if ANTHROPIC_API_KEY and LBTF_USE_CLAUDE≠0) or _compose_extractive. Both are constrained to retrieved passages; the router de-dups citations by story.
  • services/transcription.py — transcribe(path) → Transcript(text, segments, flagged_terms, duration_s). Backend chosen by LBTF_TRANSCRIBER: mock (deterministic canned transcript — what tests and demos use) or whisper. flag_terms() scans segments for a word list and records timestamps.
  • services/places.py — extract_places(db, transcript): substring match against every Location name/alias/cross_street (confidence 0.9, carries lat/lng + location_id), then a regex for "X and Y" cross streets (confidence 0.6, no coordinates — the contributor has to drop a pin).

4. Data model & the publish rule

Eight tables in models.py. The important thing is the distinction between intake objects and published objects:

TableRoleNotes
UploadintakeA transcribed video not yet attached to anything. Created by /submissions/upload.
SubmissionintakeUpload + contributor info + their self-tagged places/eras. status: pending → approved | rejected. associations (JSON) are the reviewer's time-span → location tags. Lots of denormalised copies of Upload fields.
LocationpublishedThe gazetteer. Real WGS84 lat/lng, eras list, aliases for place extraction. A pin on the map = a Location with ≥1 Story.
StorypublishedOne "perspective": a clip (optionally a start_s..end_s span of it) attached to one Location with one era. source: public | field | backfill.
Comment, Prompt, Staff, AuditEntry—Self-explanatory. Every moderation action writes an AuditEntry.
The publish rule — admin.py::_publish() Approving a submission creates one Story per reviewer association (span → location → era). If the reviewer tagged nothing, it falls back to one whole-video Story per contributor-tagged place. Zero mappable targets → 400. _resolve_location() either reuses an existing Location by id or creates a new one from name + lat/lng, so moderators grow the gazetteer implicitly. Field capture (/field-capture) calls the same _publish with source="field" and skips the queue.

JSON columns are used liberally (eras, places, segments, associations, flagged_terms). Their shapes are documented only in schemas.py (backend) and types.ts (frontend) — keep those two in sync by hand.

5. Frontend walkthrough

Providers and routing: App.tsx

DeviceProvider → ToastProvider → BrowserRouter → Suspense. Every page except Home is lazy(). Admin pages nest under AdminLayout, which redirects to /admin/login if no token and exposes useAdmin() (current staff + pending count).

Desktop vs mobile: lib/device.tsx

useDevice().layout is "mobile" if the UA looks mobile or viewport ≤ 767px, unless overridden by ?layout=. Pages that have distinct mobile designs are split into a thin switcher + two implementations sharing a hook:

  • pages/home/HomePage.tsx (useHomeData: era in localStorage, pins fetch) → HomeDesktop | HomeMobile
  • pages/contribute/ContributePage.tsx (useContributeFlow: all wizard state, upload, submit) → ContributeDesktop (4 pages) | ContributeMobile (6 steps)

Story, info and admin pages are single responsive implementations. document.documentElement.dataset.layout is set so CSS can target [data-layout="mobile"].

API client: lib/api.ts

One request<T>() wrapper over fetch with relative URLs (Vite proxies in dev). Throws ApiError(status, message), unwrapping FastAPI's detail. Admin token lives in localStorage["lbtf.admin.token"]; pass auth=true to attach it. The api object is grouped public / contributor / admin, mirroring the routers.

Styling

Plain CSS files per area (home.css, admin.css, …) with the design system in tokens.css. No CSS modules, no Tailwind. Class names are short and prefixed by area (adm-, etc.). cx() in util.ts is the classnames helper.

6. The map

One component, components/MapView.tsx (~190 lines), no map library. It is deliberately simple because the app shows a single fixed extent of West Oakland and the source scans only carry ~1,200 px of detail across it — tiles would add serving complexity for no extra detail (the reasoning is in docs/historical-maps.md).

The one invariant: lib/geo.ts::MAP_BOUNDS

Don't touch MAP_BOUNDS casually public/basemaps/*.jpg are warped to exactly this lat/lng box, and the same four numbers are hard-coded in tools/build_basemaps.py. project()/unproject() are a linear percent mapping over the box, which is correct only because the images are built on that same linear grid. Change the bounds → re-run the tool.

How MapView works

Propsera, pins: MapPin[] (real lat/lng + label/active/cluster/color), onPinClick, onTap (returns lat/lng — used for pin placement), zoomable, photo (false = always the stylised grid), children for overlay chrome.
The "plane"A ResizeObserver measures the container; a plane is sized to cover it while preserving groundAspect() (metres-wide / metres-tall of the bounds) — like background-size: cover. This is why streets don't distort on portrait phones. Zoom scales the plane; pan is a clamped px offset.
PinsEach pin is positioned at project(lat, lng) as a percent of the plane, so it stays glued to its street at any container shape or zoom.
Pointer handlingPointer capture for drag; a move under 6 px counts as a tap, which is unproject()ed back to lat/lng for onTap. Clicks on .pin, zoom buttons and the era control are excluded.
FallbackIf the era's JPG fails to load (photoOk=false) the stylised grid draws instead, from the hard-coded ROADS / TAKINGS constants in percent coordinates.

Where the map is used

  • Home (desktop 60/40 split, mobile full-bleed behind a bottom sheet) — pins + EraControl.
  • Contribute "map each place" step — onTap to drop a pin for places without coordinates.
  • Admin SubmissionDetailPage — the biggest page (370 lines): video player, clickable flagged transcript, timeline span editor, and a tagging map per span. Saves via PUT /associations; approve sends the same payload.

7. Three end-to-end flows

A. Contributor leaves a story

1 · promptuseContributeFlow fetches GET /prompts/random; shuffle excludes the current id.
2 · record / uploadRecorder.tsx (MediaRecorder → webm/mp4 blob) or UploadPicker.tsx. Nothing is sent yet.
3 · processVideo()POST /api/submissions/upload (multipart). Server writes the file, runs transcribe() + extract_places() inline in the request, returns transcript, segments, flagged terms, detected places. UI seeds the "places you mentioned" list.
4 · places → map → eras → detailsPure client state. Places with no lat/lng need a tap on the map.
5 · submitPOST /api/submissions with upload_id, places, eras, name/email, agreed_norms. Creates a pending Submission. Nothing is public yet.

B. Moderator approves

queueQueuePage → GET /admin/submissions?status=pending&q=&sort=. Tabs are just the status param (plus "flagged" = pending with flagged terms).
detailSubmissionDetailPage → GET /admin/submissions/{id}. Reviewer drags spans on the timeline, assigns each a location (gazetteer pick or map tap) and an era. PUT …/associations saves drafts; _validate_assocs clamps to duration.
approvePOST …/approve → _publish() creates Stories (one per span), sets status, writes AuditEntry. The location now has a pin on the public map and its transcript is in the RAG corpus immediately (retrieval queries the DB per request — no index to rebuild).

C. Visitor asks the archive a question

ChatPanel / useArchiveChatPOST /api/chat with the question + prior turns. Optimistic "pending" assistant bubble.
rag.answer()BM25 top-4 passages → Claude (constrained prompt, refusal fallback) or extractive stitching. Response includes mode so the UI can label it.
citationsCitationList links each cite to /story/{location_id}. Note: /story/:id is a Location id, not a Story id — the page shows all perspectives at that place.

8. Offline tools & generated assets

tools/build_basemaps.py is the only script. It never runs at build or runtime; it writes committed JPGs and caches the ~50 MB GeoTIFF downloads in tools/.cache/ (gitignored).

ScriptDepsProducesWhen to re-run
build_basemaps.pyrasterio, pillow, numpy (own venv — not in backend/requirements.txt)public/basemaps/{era}.jpg (~2000×1425) from three public-domain USGS "Oakland West" GeoTIFFs. Reprojects NAD27 → WGS84 (the datum shift is ~92 m here — don't skip it), clips to MAP_BOUNDS.MAP_BOUNDS changes, or swapping a quad edition (the SOURCES dict maps era → scan id)

USGS scans are public domain; the credit chip text lives in BASEMAPS in geo.ts. The research half of docs/historical-maps.md lists other candidate sources (Sanborn sheets, aerials, HOLC) and a MapLibre tile path if deep zoom is ever wanted — none of that is implemented on main.

9. Gotchas & conventions

  • No migrations. Schema change → make reset-db. The seed is the de facto fixture set for both manual QA and tests.
  • Eras are defined twice: backend/app/config.py::ERAS and frontend/src/lib/types.ts::ERAS (plus BASEMAPS keys in geo.ts). Adding an era touches all of them plus the tool.
  • Upload is synchronous. Transcription runs inside the HTTP request. Fine for mock; with Whisper a long clip will hold the request for minutes — a background job is the obvious next step.
  • RAG has no index. retrieve() loads every Story and recomputes BM25 each call. Fine at hundreds of stories, revisit at thousands.
  • One token per staff member. Logging in elsewhere invalidates the first session.
  • Map container needs a height. MapView measures its container; if the parent doesn't give it explicit height the map renders 0 px tall. Check layout CSS before blaming the component.
  • Tests use the mock transcriber and LBTF_USE_CLAUDE=0 via conftest.py env vars set before importing app — order matters because config.py reads env at import.
  • The frontend's types.ts is hand-mirrored from schemas.py. There's no codegen; diff them when changing a response shape.
  • Pins only appear for Locations with published stories (list_locations skips story_count == 0). A Location created by a moderator with no approved story is invisible publicly but still shows in the admin gazetteer.
  • Seed pin coordinates are "correct block" quality (verified against OSM / the 1949 quad); real submissions get moderator-placed pins anyway.
